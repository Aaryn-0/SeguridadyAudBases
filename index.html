1. Síntesis del Marco Teórico

1.1 Cambios ISO/IEC 27001:2022 vs. 2013

  • Consolidación de 114 controles (14 dominios) a 93 controles en 4 temas: Organizacionales (A.5: 37), Personas (A.6: 8), Físicos (A.7: 14) y Tecnológicos (A.8: 34).
  • Incorpora 5 atributos por control y 11 nuevos controles, destacando para bases de datos: A.8.10 (Eliminación de información), A.8.11 (Enmascaramiento de datos) y A.8.12 (Prevención de fuga de datos - DLP).

1.2 Mínimo Privilegio, Separación de Funciones y Zero Trust

  • Mínimo Privilegio (PoLP): Prohibición de permisos comodín (SELECT ANY TABLE), uso de roles acotados y revocación de paquetes UTL_FILE/UTL_HTTP de PUBLIC.
  • Separación de Funciones (SoD): Segregación en Oracle entre SYSDBA (motor), SYSKM (llaves TDE), SYSBACKUP (RMAN) y AUDIT_VIEWER (auditoría).
  • Zero Trust y Defensa en Profundidad: Validación de IP en Listener (TCP.VALIDNODE_CHECKING), cifrado TLS/NNE, filtro de filas con VPD y cifrado en disco.

1.3 Controles Técnicos: TDE, Redaction, VPD, DLP y SIEM

  • TDE (Transparent Data Encryption): Cifrado AES-256 en reposo de tablespaces y columnas usando Wallet PKCS#12.
  • Data Redaction (DBMS_REDACT): Enmascaramiento dinámico al vuelo en consultas SELECT sin alterar el dato físico.
  • VPD / RLS (DBMS_RLS): Filtrado automático por fila según el contexto del usuario (SYS_CONTEXT).
  • DLP, Backups y SIEM: Bloqueo de DB_LINKS públicos, respaldos RMAN cifrados con AES-256 y envío de UNIFIED_AUDIT_TRAIL a un SIEM externo.

1.4 Normativa Costarricense: Ley N.° 8968 y PRODHAB

  • Art. 3 y 9 (Datos Sensibles y Restringidos): Protege datos médicos, biomédicos y socioeconómicos mediante cifrado y control de acceso.
  • Art. 5 y 7 (Autodeterminación y Derecho al Olvido): Exige borrado definitivo (DROP ... PURGE, A.8.10) sin residuos en papelera.
  • Art. 10, 11 y 28-31 (Seguridad y Sanciones): Obliga al secreto profesional, Protocolo de Actuación ante PRODHAB y sanciona fugas de datos con hasta 30 salarios base.

-- 4. CONTROL A.8.11: ENMASCARAMIENTO DINÁMICO (DBMS_REDACT Y VISTA DE RESPALDO EN XE)
BEGIN
    DBMS_REDACT.ADD_POLICY(
        object_schema       => 'USR_CUSTODIO_DATOS',
        object_name         => 'PACIENTES_CONFIDENCIAL',
        column_name         => 'CEDULA_IDENTIDAD',
        policy_name         => 'POL_REDACT_PII_PACIENTES',
        function_type       => DBMS_REDACT.PARTIAL,
        function_parameters => 'VVVVFVVVVFVVVV,VVVV-VVVV-VVVV,*,1,7',
        expression          => 'SYS_CONTEXT(''USERENV'',''SESSION_USER'') != ''USR_CUSTODIO_DATOS'''
    );
EXCEPTION WHEN OTHERS THEN NULL;
END;
/

CREATE OR REPLACE VIEW USR_CUSTODIO_DATOS.VW_PACIENTES_ENMASCARADOS AS
SELECT
    ID_PACIENTE,
    CASE WHEN SYS_CONTEXT('USERENV', 'SESSION_USER') = 'USR_CUSTODIO_DATOS' THEN CEDULA_IDENTIDAD
         ELSE '***-****-' || SUBSTR(CEDULA_IDENTIDAD, -4) END AS CEDULA_IDENTIDAD,
    SUBSTR(NOMBRE_COMPLETO, 1, 1) || '*****' AS NOMBRE_ANONIMIZADO,
    REGEXP_REPLACE(CORREO_ELECTRONICO, '(^.).*(@.*$)', '\1***\2') AS CORREO_ENMASCARADO,
    CASE WHEN SYS_CONTEXT('USERENV', 'SESSION_USER') = 'USR_CUSTODIO_DATOS' THEN DIAGNOSTICO_CLINICO
         ELSE '[DATO SENSIBLE PROTEGIDO - LEY 8968]' END AS DIAGNOSTICO_CLINICO,
    DEPARTAMENTO_CLINICA,
    FECHA_REGISTRO
FROM USR_CUSTODIO_DATOS.PACIENTES_CONFIDENCIAL;

GRANT SELECT ON USR_CUSTODIO_DATOS.VW_PACIENTES_ENMASCARADOS TO ROL_ANALISTA_ANONIMO;

-- 5. CONTROL A.8.3: VIRTUAL PRIVATE DATABASE (DBMS_RLS)
CREATE OR REPLACE FUNCTION USR_CUSTODIO_DATOS.FN_VPD_FILTRO_CONFIDENCIAL (
    p_schema IN VARCHAR2, p_object IN VARCHAR2
) RETURN VARCHAR2 AS
    v_user VARCHAR2(128) := SYS_CONTEXT('USERENV', 'SESSION_USER');
BEGIN
    IF v_user IN ('SYS', 'USR_CUSTODIO_DATOS') THEN RETURN '1=1';
    ELSIF v_user = 'USR_ANALISTA_BI' THEN RETURN 'DEPARTAMENTO_CLINICA = ''EPIDEMIOLOGIA_PUBLICA''';
    ELSE RETURN '1=0';
    END IF;
END;
/
